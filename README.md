# Corporate Benefits Growth Analytics

End-to-end growth analytics for a corporate employee-benefits coupon program:
data modeling → funnel diagnosis → cohort analysis → stratified A/B testing →
ROI decisioning → offline uplift prototype → a DeepSeek-routed guarded ChatBI,
delivered as a DuckDB + Python pipeline with a 10-page Streamlit app.

> **Data disclaimer** — All data is synthetic, generated by
> `src/generate_data.py` to replicate the metric structure of a real
> (anonymized) corporate-benefits program. No client or employee data is used.

## Business context

A third-party benefits platform purchases coupons upfront, distributes them to
~5,000 employees of an enterprise client, and is paid per successful
redemption. Low redemption therefore hurts three ways: unrealized revenue,
tied-up purchasing capital, and expiry losses on non-refundable inventory.
The goal is not "maximize redemption" but **maximize incremental contribution
margin under budget, complaint, and fulfillment-capacity guardrails**.

## Pipeline

```text
generate_data.py        15 tables (dims, facts, wide table) -> DuckDB
analysis_funnel_cohort  QC (PK / time-order / consistency) + 7-step user funnel + cohorts
analysis_inventory      coupon-inventory funnel, aging, expiry-risk exposure, capital usage
analysis_experiment     SRM -> balance -> two-proportion z-tests + CI -> ROI -> heterogeneity -> guardrails
analysis_uplift         T-Learner offline prototype + propensity baseline + Qini/AUUC + top-k policy
app/app.py              10-page Streamlit app incl. metric dictionary & DeepSeek-routed guarded ChatBI
```

## Key design points

- **Two funnels, two grains.** The user-behavior funnel counts distinct users
  (issue → reach → visit → claim → redeem → fulfill); the inventory funnel
  counts coupon instances (purchase → assign → claim → redeem). Mixing grains
  is the most common source of "dashboards disagree" tickets.
- **Experiment before subsidy.** For ~1,500 visited-but-not-redeemed users,
  a stratified 3-arm test (Control / Reminder / Reminder+Reward) shows the
  reminder lifts 14-day redemption by ~6pp (significant), while the extra
  ¥5 reward adds only ~2pp (not significant, below the design MDE of ~8pp)
  — so the recommendation is targeted reminders, not blanket rewards.
- **Uplift as a staged plan, not a claim.** A single 1,500-user experiment
  cannot support a production uplift system. The repo ships an offline
  T-Learner prototype evaluated with Qini/AUUC, plus a propensity baseline
  that demonstrates *high redemption propensity ≠ high incremental effect*
  (propensity-ranked top-20% shows ~0 lift; uplift-ranked top-20% shows
  double-digit lift). Deployment would require fresh holdout validation.
- **DeepSeek-routed guarded ChatBI.** Questions route through DeepSeek into a
  whitelist of vetted SQL templates — read-only, enterprise-scoped, PII-free —
  with result validation and a query log. DeepSeek selects templates only; it
  does not generate free-form SQL. If no API key is configured, the app falls
  back to synonym-based retrieval. Causal "why" questions are refused by design
  and redirected to the experiment module.

## Metrics (from the built-in metric dictionary)

30 metrics across North Star / funnel / experiment / finance / inventory /
guardrail / long-term categories, each documented with definition, numerator,
denominator, grain, exclusion rules, source tables, and live SQL. Headline
values in the synthetic dataset: issue 98.8%, reach 92.4%, visit 63.6%,
claim 47.3%, 14-day redemption 31.2%, fulfillment 95.9%, budget utilization 68.5%.

## Quickstart

```bash
pip install -r requirements.txt
python src/generate_data.py              # regenerate the DuckDB (optional; shipped)
python src/analysis_funnel_cohort.py     # QC + funnel + cohorts
python src/analysis_inventory.py         # inventory funnel + expiry risk
python src/analysis_experiment.py        # SRM + lift + CI + guardrails
python src/analysis_uplift.py            # T-Learner + Qini + top-k policy
streamlit run app/app.py                 # dashboard + guarded ChatBI
```

## Streamlit Cloud settings

Use Python **3.11** for the most reliable scientific-package compatibility.
In **Advanced settings → Secrets**, add the DeepSeek credentials in TOML format:

```toml
DEEPSEEK_API_KEY = "your_real_deepseek_key"
DEEPSEEK_BASE_URL = "https://api.deepseek.com"
DEEPSEEK_MODEL = "deepseek-v4-flash"
```

`DEEPSEEK_BASE_URL` and `DEEPSEEK_MODEL` are optional because the app has these
defaults built in. Keep the API key in Streamlit Secrets only; do not commit it
to GitHub.
